# Why there is no front end

The weekly job is a discussion about role coverage, evidence and follow-through. A database plus a coding agent keeps those records and prepares the discussion. `npm run view` produces read-only HTML pages; `npm run docs` prepares handover and development drafts in your brand. There is no web server or interactive staff portal.

A screen gives you visual org-chart editing, drag and drop, forms for managers, mobile entry and individual sign-in. This base does not provide those features, offline mobile synchronisation, live collaboration or an HR-system connection. Local PGlite supports one process at a time. Use a reviewed shared Postgres deployment for concurrent operators.

Generated HTML is a snapshot, not a live dashboard. Regenerate after changing records. Do not publish staff reports on a public website. A coding agent can change the schema or add a view through a reviewed migration and tests. Your organisation remains responsible for access, privacy and decisions about people.

Enterprise DNA can build the screens and connections your team needs on the same records, and operate them through Omni by Enterprise DNA. The database remains yours.
